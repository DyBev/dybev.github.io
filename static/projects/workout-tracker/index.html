Workout Tracker

Github repository

A barebones workout tracker for me to use as an exploration project for core concepts like infrastructure, Architecture and Design

Initially I used Generative AI to put together a POC that I have been using since 2026.03 and I'm going to continue working on the project looking for that sweet 1.0 release. Recently I've been focused on some of the more mundane requirements for me such as on-demand preview environments to allow me to test my changes as I'm working out, as part of that I've been improving my infrastructure by migrating it to be defined declaritively with Terraform/OpenTofu

My General approach to this project is currently driven by 2 main factors, my need for a flagship project to share with my peers and use as an exploration ground and my need to track my workouts in the hopes of improving my consistency in the gym and track my progress, so a lot of the features are on a strictly need to have basis. As well as the obvious of reducing my costs to run this projects all my decisions take into account the cost aspect

Of course the project is built for me and ultimately I do not think that this project is something that is going to be my final flagship but for the time being it is great and will really help me in defining the types of standards I want my future work to follow

Details

Read about the details and choices I've made

Database

AWS - DynamoDB

  • Serverless Document based database, felt like a very easy choice when combined with my choice for Lambda functions in order to interact with the database as the AWS.Aurora service requires paying for the connection pool for Database<=>Lambda connections without overspending
  • PK/SK base making it easy to manage and fetch data, along with a global index on the workouts to allow for workout fetching
  • Multiple entries for: Workouts and Saved-Exercises
  • Data is structured in a way where I can migrate the database to a Relational style database

    • Front-end framework

    Expo React(Native)

  • React is really becoming my bread and butter (well it has seemingly infected the entire internet) as a front-end framework and workflow React really does shine
  • I chose Expo React(Native) as I would like to have this project become a real app that could be installed on mobile devices, I think that would be the end goal of this project the 1.0 release would come with a App store release
  • My comfort with React and TS in general made it really easy to get the POC down (with the help of GenAI to get the volume of code down) and extending it has become a breeze

    • Backend (APIs)

    Golang, AWS ApiGateway + Lambda

  • As with the DynamoDB a serverless service makes it a simple choice to solve the cost perspective
  • Golang as my language for choice my first experience with Golang was with my Fantasy Football app where I re-wrote my Python BE into Golang and that experience made it a really easy choice to pick it for this too. The thing I like about Golang is the error handling via the error return rather than TRY{}CATCH{} blocks, I find try catch blocks to be a passive way to handle errors, but Golang makes error handling an active thought in my opinion which has helped me as I've been able to add extra logging about the error locations etc when I've been attempting to debug things

    • What would you do if?

    Essentially an self-appointed FAQ

    What would happen at volume x?

    All about costing!

    Well at the moment as it stands with my "napkin" math, I shouldn't see any substantial costs until I hit about 10k users who are registering ~23 workouts per month

    My understanding is that at that volume is the best place for me to look towards changing up the infrastructure

    At this moment in time I would probably change to use a Bare-metal service as a starting point, porting the Golang code to be run as a single server would not take too much so that would be a easy first win

    I would still continue using the AWS DynamoDB service until I can do a full service performance test, if I'm going to start using bare-matal providers I would want to really consider the best choices for me before making any changes to the database
